# ML Developer — highlights для объяснений

## Цель

Дать каждой выбранной карточке короткую и отличимую особенность, взятую из описания подрядчика. Не обучать модель на 66 профилях и не отдавать модели решение о доступности, бюджете или порядке выдачи.

## Контекст решения

- Каталог содержит 66 профилей, описания на русском; 13 записей помечены `synthetic`.
- Основной matching структурирован и детерминирован: город, категория, дата, формат, бюджет и опциональные язык/длительность.
- Полный CSV уже находится в `../data/contractors.csv` и содержит `description`, календарь и флаги происхождения данных.
- Можно применить уже доступный LLM API или компактную детерминированную обработку; никаких обязательных внешних зависимостей во время demo-запроса.

## Задачи по порядку

1. Сразу выбери минимальный способ обработки всего `../data/contractors.csv`: предпочтительно детерминированное извлечение/шаблоны; LLM API использовать только если ключ уже доступен.
2. Подготовь highlights для полного каталога (максимум 1–2 коротких конкретных факта на профиль); пропусти общую рекламную формулировку.
3. Сохрани исходный `id` и подтверждающий фрагмент для каждого highlight; не добавляй выводы, которых нет в исходном `description`.
4. Передай Fullstack `data/highlights.json` и инструкцию. Не трать время на ML API-сервис.

## Data contract: `data/highlights.json`

```json
[
  {
    "id": "HK-90001",
    "highlights": ["Авторские композиции под цветовую палитру мероприятия"],
    "evidence": ["собираем композиции под цветовую палитру мероприятия"]
  }
]
```

Массив может быть пустым. `id` должен точно совпадать с профилем. Не пересчитывать цены, города или занятость и не превращать описание в подтверждённый атрибут, которого нет в исходном профиле.

## Интеграционная передача Fullstack

- Файл: `data/highlights.json`.
- Сопоставление: по `id`.
- Backend использует highlight только как одну из причин карточки; совпадения из структурированных полей формирует сам.
- Runtime вызовов внешней модели нет.
- При отсутствии highlight показывать только конкретные структурные причины.

## Статус

- Сейчас: обработать доступный полный CSV; при нехватке времени подготовить highlights для шести демо-кандидатов и редкой категории.
- Блокер: нет.
- Готово, когда: для нужных профилей есть короткие фактические highlights с evidence; формат можно загрузить по `id`; выдача приложения от них не зависит.

## Решения / вопросы

- Файл с исходными 66 профилями должен быть добавлен в workspace до пакетной обработки.
- Не использовать LLM для создания уникальных «причин» без источника из профиля или запроса.
