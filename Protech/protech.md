# PropTech Developer — предметные правила рекомендаций

## Цель

Сделать подбор честным для заказчика мероприятия: показывать только профили, подходящие по указанным требованиям и не занятые в точную дату, и объяснять дефицит выбора понятной причиной.

## Что известно из условия

- Категории включают ведущих/фотографов и редкие позиции вроде флористов, декораторов, подарков, ведущих церемонии, фото-видеобудок, отелей и инструменталистов.
- Города: Алматы, Астана, Зарубежье.
- Форматы: свадьба, той, корпоратив, конференция, юбилей, день рождения.
- Языки: русский, казахский, английский.
- `max_hours: null` означает, что работа не привязана к присутствию (например, флорист/декоратор/сувениры).
- Календарь покрывает 23.09.2026–31.12.2026. Плотная занятость в декабре ожидаема.
- 13 профилей synthetic; часть городов/цен imputed — флаги видимы пользователю.
- HTML preview показывает число занятых дней, но не сам календарь.

## Зафиксировать правила и передать Fullstack

1. `category_unavailable`: до фильтрации по остальным критериям в выбранном городе нет профиля с нужной категорией.
2. `no_eligible_candidates`: профиль категории в городе есть, но реальные ограничения отсекли всех; UI называет фактические причины: дата занята, цена выше бюджета, формат не поддерживается и/или указанный язык/длительность не подходят.
3. `matched`: вернуть до трёх прошедших кандидатов. Если их 1–2, показать фактическое количество и причину, почему меньше трёх.
4. Занятость проверять точной датой по массиву `busy_dates`; «занято 42 дня» недостаточно, чтобы объявить дату занятой или свободной.
5. Цена сравнивается с бюджетом в KZT: `price_from_kzt <= budgetKzt`; слово «от» сохранять в UI, не выдавать начальную цену за итоговую смету.
6. Формат обязателен и должен точно совпадать с одним из `event_formats` профиля.
7. `language`/`maxHours` — необязательные ограничения. Если язык задан — должен быть среди языков профиля. Если `maxHours` задан и `max_hours` числовой — числовой лимит должен покрывать запрошенную длительность; `null` означает неприменимо, а не ноль часов.
8. Не обещать оформление брони или подтверждение исполнителя; продукт только рекомендует на основе каталога.

## Три демонстрационных сценария

Три реальные запроса уже рассчитаны по `../data/contractors.csv` и записаны в общий README:

| Тип | Условия выбора | Что должно быть видно |
|---|---|---|
| Плотная категория осенью | Ведущий (15 профилей) или Фотограф (12), дата осенью, на которую часть кандидатов занята | 1–3 прошедших кандидата, порядок повторяем, отдельное объяснение каждого |
| Редкая категория | Категория, где в данных 3 профиля | Показать реальное количество после фильтров и факты по каждому |
| Без результата | Город+категория существуют, но выбранная дата/бюджет/формат исключает всех | Показать конкретную причину, не пустой экран |

Для одной плотной категории также выбрать вторую дату, у которой занятость меняет результат; утверждать смену выдачи только после проверки `busy_dates`.
