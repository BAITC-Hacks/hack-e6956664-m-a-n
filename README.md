# HackAlem AI — умный подбор подрядчиков

## Problem

Заказчику нужно выбрать подрядчика из каталога, а не просматривать длинный список и вручную сверять даты, цены и особенности профиля.

## Solution

Веб-приложение проверяет жёсткие условия по каталогу из 66 профилей и показывает до трёх вариантов с объяснением и цитатами из описания. Если условиям никто не соответствует, сервис показывает причину, минимальную цену среди остальных совпадающих условий и ближайшие даты с доступными кандидатами.

## Key differentiator

Фильтры допустимости и semantic AI разделены: модель не может вернуть занятого подрядчика, нарушить бюджет, формат, язык или длительность. Для каждого результата доступно проверяемое объяснение по данным каталога. Повторяемый fallback оставляет сервис работоспособным без внешнего AI.

## Demo

Пять кнопок на стартовой странице покрывают популярную категорию, другую дату, редкую категорию, бюджет без совпадений и категорию, отсутствующую в городе. Интерфейс также принимает свободное пожелание к стилю.

## Architecture

Node.js 20+ HTTP server, нативные модули, HTML/CSS/JavaScript и `data/contractors.csv`. Внешний AI вызывается только с backend. При запуске все 66 описаний и их предложения предвычисляются в одном или нескольких пакетных запросах и кэшируются в памяти процесса; на запрос пользователя вызывается только embedding его пожелания. База данных и отдельный ML-сервис не нужны.

## Recommendation pipeline

Город и категория → формат → точная дата занятости → бюджет → необязательный язык → необязательная длительность → семантическое ранжирование пожеланий → цена и ID как стабильный tie-break → доказательства из описания.

## Hard eligibility

Подрядчик не попадает в выдачу, если не проходит город/категорию, формат, точный busy date, бюджет, указанный язык или длительность. `max_hours` со значением null означает, что ограничение длительности в источнике неизвестно, а не что подрядчик неограниченно доступен.

## AI semantic ranking

Если заданы `AI_PROVIDER=openai` и `AI_API_KEY`, `text-embedding-3-small` сравнивает embedding пожелания с предвычисленными embeddings полных описаний и сортирует только допустимые профили по cosine similarity. При равенстве используются цена по возрастанию, затем ID. OpenAI описывает этот embedding endpoint для multilingual similarity/retrieval; модели `text-embedding-3` показывают более высокую multilingual performance ([API guide](https://developers.openai.com/api/docs/guides/embeddings)). Проценты качества не показываются. Без ключа, пока cache разогревается, при malformed response, network failure или timeout приложение использует цену и ID, а пожелание не влияет на порядок.

## Evidence & explainability

Eligibility explanation возвращается отдельно в `eligibilityReasons`; `recommendationReason`, `evidence` и необязательный `semanticScore` идут отдельными полями. При активном AI фрагменты описания сортируются по similarity с пожеланием; без AI лексическое пересечение может подсказать цитату, но не меняет порядок карточек. Фрагменты берутся дословно из `description`; LLM генерации фактов нет.

## No-result handling

`category_unavailable` означает, что категории нет в этом городе. `no_eligible_candidates` означает, что кандидаты категории есть, но все исключены фильтрами. Вторая ситуация показывает funnel причин, минимальную цену при совпадении остальных ограничений и до трёх ближайших дат, где доступен профиль.

## Dataset

`data/contractors.csv` — исходный анонимизированный каталог из 66 записей с точными `busy_dates`. Флаги `synthetic`, `city_imputed` и `price_imputed` сохраняются и помечаются в карточках. Диапазон выбора даты явно задан в `src/catalog.js` как 2026-09-23–2026-12-31, а не вычисляется по занятым дням.

## Quick start

```bash
cd <project-root>
npm install
npm start
```

Откройте http://localhost:3000. Для multilingual semantic ranking скопируйте `.env.example` в `.env` и задайте `AI_PROVIDER=openai`, `AI_API_KEY` и при необходимости `AI_MODEL`. По умолчанию используется `text-embedding-3-small`; ограничьте ключ только embeddings endpoint, если настройки проекта это позволяют. Без ключа приложение полностью работает с fallback. `.env` игнорируется Git.

## API

- `GET /api/health` — состояние приложения, объём каталога и состояние AI/cache (`warming`, `ready`, `unavailable`).
- `GET /api/meta?city=Алматы` — значения формы и явные границы дат.
- `POST /api/recommendations` — подбор. Обязательные поля: `city`, `date` (`YYYY-MM-DD`), `eventFormat`, `category`, `budgetKzt`. Опциональные: `language`, `durationHours`, `preferences` (до 500 символов). Ответ сохраняет legacy `reasons` и добавляет `eligibilityReasons`, `recommendationReason`, `evidence`, `semanticScore`, `aiStatus`, `rankingMode`, `eligibleCount`.

## Demo scenarios

1. Алматы · 07.10.2026 · свадьба · Ведущий · 2 000 000 ₸.
2. Та же заявка на 03.10.2026: занятость меняет кандидатов.
3. Алматы · 07.10.2026 · свадьба · Инструменталист · 600 000 ₸.
4. Ведущий · бюджет 500 000 ₸: нет подходящих кандидатов.
5. Зарубежье · Флорист: категория отсутствует в городе.
6. Алматы · 15.10.2026 · корпоратив · Ведущий · 1 500 000 ₸ · русский · 6 ч · пожелание «интеллигентный ведущий с опытом бизнес-мероприятий, без навязчивого юмора». Реальные hard filters оставляют семь профилей; среди них `HK-44733` (10+ лет опыта, интеллигентный стиль, большие бизнес-форумы). Без AI price-only первый `HK-44923` (650 000 ₸); semantic ranking должен сравнить их embeddings, и backend/UI покажут только фактический порядок и извлечённые цитаты. Точные semantic score и победителя нужно снять после настройки API key — в dev-среде ключ отсутствует.

## Determinism

Без пожелания действует цена по возрастанию и ID. С AI — cosine similarity по убыванию, затем цена и ID. Embedding API может изменить выдачу только когда пользователь ввёл пожелания и сервис доступен.

## AI fallback

При отсутствии ключа, cache warmup failure, неверном ответе провайдера, сетевой ошибке или превышении `AI_TIMEOUT_MS` API продолжает подбор с сортировкой цена → ID. `/api/health` показывает, готов ли embeddings cache; в recommendation diagnostics возвращаются `aiStatus`, `rankingMode`, `eligibleCount` и причина fallback. По умолчанию timeout — 4500 мс; AI код выполняется только на backend, ключ не передаётся браузеру.

## Limitations

Каталог анонимизирован и может содержать синтетические профили и восстановленные значения. Цена указана «от». Неизвестные ограничения часов не считаются доказательством доступности. Приложение не бронирует подрядчиков и не подтверждает фактическую занятость сверх данных CSV. Feedback-кнопки демонстрационные и не сохраняют данные.

## Production roadmap

Подключить реальные календарные синхронизации, верификацию подрядчиков, отзывы, число завершённых событий, response/cancellation rate, портфолио, фактические цены, радиус выезда, оборудование и число гостей. Затем можно добавить reliability/availability confidence и ранжирование по подтверждённой обратной связи. Переход к БД или поисковому индексу оправдан при подключении живых vendor-профилей и частых обновлениях, а не для текущего каталога из 66 строк.

Для хостинга подходит обычный Node web service (например, Render): build command `npm install`, start command `npm start`, health path `/api/health`. `PORT` читается из окружения. Добавьте `OPENAI_API_KEY` как секрет хоста только если нужно включить semantic ranking. Render принимает Node web services с build/start commands и health path в настройках сервиса ([документация](https://render.com/docs/web-services)).

### Repository layout note

В текущей рабочей копии есть два `.git`: внешний репозиторий отслеживает `hack-e6956664-m-a-n` как gitlink; внутри находится отдельный клон с тем же origin URL. У внешнего репозитория нет `.gitmodules`, поэтому обычный fresh clone может не содержать код из внутренней папки. Не удаляйте ни один `.git` и не пушьте до согласования с командой. Проверьте обе истории и origin, затем закрепите один репозиторий, который содержит файлы приложения непосредственно в его корне. После этого проверьте `git clone` именно этого URL и выполните команды Quick start.
